# SpanTwin vibration-only daily analysis engine

This is the backend-ready analysis layer for daily distributed-fiber vibration reports.

## Inputs used

Only vibration measurements:

```text
date, fiber_position_m, window, vibration_value
```

`window` must be one of:

- `pre_event`
- `passage_event`
- `post_event`

No temperature, traffic, vehicle speed, vehicle mass, weather, or environmental-compensation feature is accepted or used.

## What it returns

The engine creates a JSON report containing:

- per-position pre-event, passage-event and post-event vibration values,
- normalized vibration residual,
- data-quality checks,
- contiguous anomalous fiber positions,
- probable bridge zone,
- persistence across previous report summaries,
- an inspection recommendation.

## Run

```bash
python analyze_daily_report.py \
  --input example_daily_report.csv \
  --history history.json \
  --output report.json
```

`history.json` is optional. If supplied, it must be a JSON list of previous report summaries generated by this tool.

## Spatial continuity safeguard

A probable zone needs at least three adjacent virtual fiber positions. Adjacent flagged positions must also be no more than 1.5 times the report's median fiber-position spacing apart. This prevents an unobserved cable gap from being presented as one continuous zone. The report records observed median spacing and maximum position gap as data-quality values.

## Interpretation

A result such as `East deck-girder / 72–88 m` is a **probable vibration-deviation zone** for inspection. It is not an exact crack coordinate and does not prove structural failure.
